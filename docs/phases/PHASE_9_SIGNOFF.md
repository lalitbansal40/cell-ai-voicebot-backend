## 5. Deviations from the plan

All recorded in the [plan changelog](PHASE_9_PLAN.md#changelog) (T9.1, Batch 1, Batch 2 and Batch 3 entries). Batch 3 in short: the WhatsApp page shell and `/data-deletion` page came with T9.8 (the routes need them); fake signup codes carry a nonce (an identical second signup — a reconnect — would otherwise reuse a single-use code); the only-WABA number keeps the default label "WhatsApp number" (Meta tells no name before the number exists); the E2E backend runs with its own fake secret and verify token (`e2e/env.ts`); the data deletion page shows "completed" right away (the deletion runs inside the callback); the simulator got a 16th kind `phone_number_added`.

Real bugs found and fixed (each with a regression test proven to fail first): **Batch 1–2** — a restriction taken from the phone status never lifted (found by the health tests before commit), quality / name notifications could double between a webhook and its re-check (moved into the sync); **Batch 3** — the dev simulator sent `phone_number: ""` for numbers without a display number, so Meta's schema failed and the simulated effect never happened (`175f6c5`). Test-only: a Phase 8 dispatcher test raced its own wake on a loaded machine (`b57e192`, also failing on `main`).
