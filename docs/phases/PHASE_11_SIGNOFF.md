# Phase 11 — Sign-off

**Date:** 2026-10-24 · **Branch:** `feature/phase-11-templates-billing` (both repos, not merged) · **Plan:** [PHASE_11_PLAN.md](PHASE_11_PLAN.md) · **Tracker:** [PHASE_11_TASKS.md](PHASE_11_TASKS.md) · **Run prompt:** [PHASE_11_PROMPT.md](../prompts/PHASE_11_PROMPT.md) · **ADR:** [0039](../adr/0039-whatsapp-templates-billing.md) · **Real-WABA checklist:** [setup guide §14](../setup/meta-whatsapp.md)

**Verdict:** ✅ Phase 11 (WhatsApp Templates + WhatsApp billing) complete — all 12 tasks done. **"Done when"** is proven by Playwright on the fake Meta provider (frontend repo, `e2e/templates-*.spec.ts`):

- **Template lifecycle:** an owner builds a template with an image header, two variables, a footer, a quick reply and a URL button with a suffix → **In review** → the fake review approves it live (bell) → it goes to a customer whose 24-hour window is closed, with the contact's name and a custom field, the live preview and the cost line → ticks reach Read. A rejected template shows its reason → **Edit and resubmit** → approved.
- **Exact charge:** the wallet line "WhatsApp · Utility · India" equals the ₹0.14 the dialog showed (Meta's ₹0.115 + 15 % rounded up to the paisa). An account markup of 50 % makes it ₹0.18. An undeliverable template and a free service reply release their hold; a billable reply is captured.
- **Money rules:** an empty wallet refuses the send with "Add money…" and holds nothing; a reached WhatsApp budget refuses; Meta billing a released message charges it late (balance below zero + bell); a customer-pays number shows "Billed by Meta…" and writes no wallet line.
- **Marketing rules:** STOP (also a DND entry) blocks every template; an opted-out contact without the DND entry gets utility but not marketing; "stopped marketing" (webhook or Meta's 131050) is refused; one marketing template per customer per 24 h; a paused template is not offered; a recategorised template shows Marketing (+ bell).
- **Call permission template** created ready-made and approved; **superadmin** imports the rate card (diff) and sees the margin report; roles: viewers / agents read only (agents send), impersonating superadmins read only, another account gets 404.

The real-WABA checklist (template approved on a real test WABA, a delivered charge reconciled with `pricing_analytics`) is written and runs in Phase 13. **Phase 12 can start.** Merging the branches is a project-lead decision after review.

## 5. Security / money checklist and deviations

- Customer data (variable values, rendered text, phones, names) never in logs, audit, notifications, job data or account events — unit tests (`templates/webhooks.test.ts`, `templates/send.test.ts`: notifications and audit carry ids / names of templates only) and the log greps (P11-B2 manual check, E2E §7).
- Template bodies never logged; example uploads sniffed (magic bytes vs header format and declared type), file names sanitised, signed links.
- Meta's cost, the markup and the fee are superadmin-only: the account ledger strips them (`billing/wallet-api.test.ts`, regression of `8c11ea8`), price preview / wallet prices return selling prices only (`templates/routes.test.ts`), the frontend never shows them outside superadmin views.
- Money only through the engine (`security/money-writes.test.ts`); held rows equal the wallet hold and the ledger equals the balance after every billing scenario (`expectWalletConsistent`); idempotency keys `wa-hold-<clientId>`, `wa-capture-<messageId>`, `wa-late-<messageId>`.
- Impersonation read only (backend route tests, fe permission tests, E2E roles); another account's template ids → 404.
- gitleaks both repos: no leaks; `console.log` in `src`: 0 / 0; no network in tests (Meta hosts only in allowlists, defaults, fake URLs and stub-server fixtures).

Deviations (all in the [plan changelog](PHASE_11_PLAN.md#changelog)): the ledger rows carry the chat id (`breakdown.waConversationId`) for "Open the chat"; the admin account detail returns the price override; the validator cases are shared through a JSON fixture copied into the frontend; the Phase 9 Meta billing control moved into the account's WhatsApp billing region; the superadmin billing hooks live in `features/templates/queries.ts`; WhatsApp STOP adds a DND entry (Phase 10 design), so the "utility to an opted-out contact" case is proven after removing the DND entry; the fake's `_reject` knob approves an edited template; every Phase 10 inbox E2E spec funds the wallet.
