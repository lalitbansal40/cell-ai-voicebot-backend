# Plan: finish the IVR (Cell24x7) work, a template-create API, and the Pinnacle API for superadmins

25 Nov 2026 · Status: **plan only, nothing built**

Three parts:

1. **IVR / recorded voice (Cell24x7 · `voice.truebeeps.com`)**: finish what's left.
2. **Public API: template create.** Templates can be created, submitted and deleted with an API key, and the docs show it next to the other APIs.
3. **Pinnacle partner API:** shown **only to superadmins**, with the API key configured for that account's managed number. Shown only when a key is configured.

The same rules apply to all three:

- No new env variables. Any new setting is a constant in `src/config/*.ts`.
- No SSH access to the server, so every check must be possible from the panel.
- A secret is never printed in a log, an audit row, an API answer or an export.
- Release flow: `main` in both repos, then `scripts/sync-client-repo.sh`.

## Part 2: template create in the public API

### 2.1 Decisions

| #    | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-D1 | New API key scope **`templates:write`** (group WhatsApp): "Create, submit, edit and delete WhatsApp templates". Permission `templates.manage`. Keys never get the call-permission template routes, and never `templates.sync`.                                                                                                                                                                                                                                                                                                                                                                                                        |
| T-D2 | Routes opened to keys with `access({ permission: 'templates.manage', scope: 'templates:write' })`:<br>• `POST /api/v1/whatsapp/templates` (create a draft; optional `submit: true` + `channelId` submits it to Meta at once)<br>• `POST /api/v1/whatsapp/templates/{id}/media` (header example: image / video / document)<br>• `POST /api/v1/whatsapp/templates/{id}/submit`<br>• `PATCH /api/v1/whatsapp/templates/{id}` (edit, under Meta's edit limits)<br>• `DELETE /api/v1/whatsapp/templates/{id}` (`?scope=name` for every language)<br>• `GET /api/v1/whatsapp/templates/{id}` (scope `templates:read`, detail with the body) |
| T-D3 | `GET /whatsapp/templates` with an API key today shows only APPROVED templates. Add `?status=` filtering for `templates:write` keys (so they can see their PENDING / REJECTED ones). A `templates:read`-only key stays APPROVED-only.                                                                                                                                                                                                                                                                                                                                                                                                  |
| T-D4 | Actor for an API key: `actorOf(req)` gives `{ type: 'api_key', id: keyId, accountId }`. Audit and `createdBy` store the key (`createdByKeyId`). `blockWhenImpersonating` doesn't apply to keys. The rate limit is per key: `templates:<keyId>` (`createsPerHourPerUser` = per key).                                                                                                                                                                                                                                                                                                                                                   |
| T-D5 | `Idempotency-Key` on create / submit (the existing middleware). The same key + same body → the same template.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| T-D6 | Validation and Meta errors are the same as in the dashboard (`validateTemplate`). Errors are documented: `TEMPLATE_INVALID` (field paths), `TEMPLATE_NAME_EXISTS`, `TEMPLATE_LIMIT_REACHED`, `TEMPLATE_EDIT_LIMIT`, `META_API_ERROR`, `WHATSAPP_CHANNEL_NOT_READY` (match the names in `error-codes.ts`).                                                                                                                                                                                                                                                                                                                             |
| T-D7 | Managed (Pinnacle) numbers: submit goes through `clientFor` to Pinnacle, as in the dashboard. Nothing new.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| T-D8 | Status change: a webhook event **`template.status_changed`** (approved / rejected with reason / paused / disabled), if it isn't in the public webhook list yet, plus payload docs.                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

## Part 3: Pinnacle partner API, for superadmins only, with the account's key

### 3.1 Decisions

| #    | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P-D1 | **Who sees it:** only `platformRole: superadmin`, either on the Admin pages or in a Full-access login-as session on that customer's account. A customer owner / admin, a View login-as and resellers **never** see it. The backend checks it (`requirePlatformAdmin`), not only the UI.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| P-D2 | **When it shows:** only when the account has at least one managed number (`provider: pinnacle`, not disconnected) **with an API key configured** (`tokenSealed` present, `pinnacle.keyLast4` set). Otherwise: "No partner API key configured for this account — add a managed number in Admin → account → WhatsApp."                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| P-D3 | **Where:**<br>(a) Admin → Accounts → account → WhatsApp → each managed number → a **"Partner API (Pinnacle)"** panel<br>(b) for a superadmin in Full access, in the customer's **Settings → API keys** page, below the normal API reference, a **"Partner API (Pinnacle) — superadmin only"** card with the same content.<br>The public `/api/docs` (Swagger, no login) **never** shows it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| P-D4 | **Key display:** masked by default `pin_••••••••ab12` (last 4). **Reveal** needs a step-up (the superadmin's own password + two-step code, as for SAC danger actions). The key is never logged.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

| P-D7 | **Try it (safe console):** the superadmin can run **read-only** operations through our backend proxy: `getuserdetails`, `getwebhook`, `business/{phone}`, `phone_numbers`, `whatsapp_business_profile`, `message_templates` (list). The key stays on the server and never goes to the browser. Write operations (send a message, setwebhook, template create, register) are **not** in the proxy. The docs show them only as curl. Proxy limit: 20 per 10 min per superadmin. Each run is audited (`whatsapp.partner_api_called`, `{ op, channelId, status }`). The answer passes through phone masking (≥ 8-digit runs → `…last4`).                                                                                                                                                                                                                                                                       |

No migration.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
