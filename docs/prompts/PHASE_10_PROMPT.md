**Run-prompt refinements (locked now, recorded in the plan changelog at STEP 0):**

- **Uploads collection `inboxUploads`** (tenant) — the `mediaToken` returned by `POST /inbox/media` is the upload **id** (ObjectId string), valid only for the same account **and** user, unused, not expired. On message creation the upload's fields are copied into `message.media` and the upload row is **deleted** (the stored file now belongs to the message). Unused uploads expire after 24 h (retention job deletes file + row).
- **Storage keys** use the existing `storageKey()` helper: uploads `area: 'inbox-uploads'`, `id: <uploadId>`; inbound downloads `area: 'inbox-media'`, `id: <messageId>`; voice remux output overwrites the upload's key with `ext: 'ogg'`. (Plan §1d / §1f path literals are replaced by these.)
- **Media download host allowlist (SSRF guard):** the URL returned by `GET /{media-id}` must be `https:` and its host must end with one of `META_MEDIA_HOST_SUFFIXES = ['.fbsbx.com', '.fbcdn.net', '.whatsapp.net', '.facebook.com']` (re-check against Meta docs); the fake provider additionally allows exactly the `APP_URL` origin (non-production only). Redirects are not followed (`redirect: 'error'`).
- **Outgoing order per conversation:** the send job sends only when no **earlier** (`at` older) message of the same conversation is still `queued`; otherwise it re-delays itself 500 ms (`job.moveToDelayed`, max 20 times, then sends anyway and logs `order_wait_exhausted` with ids only).
- **Emoji picker:** own lightweight component with a static emoji data file (~300 common emojis in 8 categories + recent emojis in `localStorage`), lazy chunk — **no new emoji library**.
- **Lightbox / players:** own MUI `Dialog` lightbox; native `<audio controls>` / `<video controls>` — no player library.
- **Fake auto statuses** are disabled in unit / integration tests (`FAKE_META_STATUS_DELAYS_MS=off` in the vitest env); tests drive statuses explicitly through the simulator / webhook helper.
